第1步

项目初始化

搭建标准化项目骨架，确保结构一致

📁

标准化目录

CLAUDE.md / README.md / .gitignore / .github/ / .vscode/ / docs/ / src/ / tests/ / .claude/

📜

CLAUDE.md — 项目"宪法"

定义项目概览、开发规范、工作流，约束 AI 行为

✗ 混乱的做法

  • 每个项目从零搭目录，风格各异
  • 团队和 AI 不知道规范
  • 不同项目配置五花八门

✓ 好的做法

  • 标准化模板一键生成
  • CLAUDE.md 就是"宪法"
  • .vscode/ + .github/ 统一配置
第2步

需求梳理 & 架构设计

将业务想法转化为结构化文档，一切后续工作的唯一依据

requirements.md

📋 需求总纲

  • • 项目简介 & 背景痛点
  • • 可衡量的项目目标
  • • 分阶段目标（试点→推广→全覆盖）
  • • 功能模块清单 + 优先级
  • • 系统集成关系
  • • 非功能需求（性能/安全/兼容性）
architecture.md

🏗️ 架构设计

  • • 技术选型（前端/后端/数据库）
  • • 分层架构图（接入→应用→流程→集成）
  • • 模块划分与交互关系
  • • 设计原则
  • • 主数据管理
  • • 决策记录 (ADR)
第3步

文档归类管理

按模块建立清晰的文档体系，避免混乱

docs/
├── requirements.md // 需求总纲
├── architecture.md // 架构设计
├── 01-蓝图方案/
├── 02-业务需求/
├── HR人事模块/
├── 行政模块/
├── 生产模块/
└── 通用模块/
├── 03-原型方案/
└── 04-PRD/
按模块不按类型
业务需求按「模块」分类（HR/行政/生产），而非文件类型
README 导航
每个模块目录放 README.md 作为入口
归类即整理
新文件立刻归类，不堆积到 docs/ 根目录
可自动化
用 organize-docs skill 自动扫描归类
第4步

原型设计

三端合一的 HTML 可交互原型

📱 手机端 (m-page)

底部 Tab 导航 · 页面 ID: mp-{模块名}
导航函数: mNav('page-id')

💻 PC 端 (pc-page)

左侧导航 · data-pc 属性绑定 · 页面 ID: pc-{模块名}

🔐 管理门户 (portal-page)

左侧导航 · data-portal 属性绑定 · 页面 ID: portal-{模块名}

✗ Axure / Figma

  • 需专门软件安装
  • 无法做自动化校验
  • 不能 Git diff
  • 分享需额外部署

✓ HTML 原型

  • 浏览器直接运行
  • 可自动化断链检查
  • 可 Git 提交做 diff
  • 分享链接即可查看
第5步

原型验证

自动化质量门禁，Axure/Figma 做不到的事

1
读取 HTML 原型文件
定位 .html 并读取完整内容
2
提取页面定义
m-page / pc-page / portal-page
3
提取导航引用
mNav调用 / data-pc / data-portal / onclick函数
4
逐项校验
目标存在? 函数定义? ID重复?
5
输出验证报告
通过/失败，断链清单
✅

人事通.html 验证结果

22 个移动页面 · 16 个 PC 页面 · 9 个门户页面

全部通过，零断链，零重复

第8步

Git 提交 & 版本管理

每次重要变更对应一个提交，形成可追溯的演进历史

📝 提交规范

  • • 提交信息使用中文
  • • 格式：{动词}{名词} — {补充说明}
  • 示例：
  • 「初始化项目结构」
  • 「新增 organize-docs skill」
  • 「人事通原型 V1.0 — 三端交互原型」

📋 提交时机

  • • 🟦 项目初始化 — 骨架目录 + CLAUDE.md
  • • 🟦 文档更新 — 需求、架构文档变更
  • • 🟩 文档归类 — 移动文件后的目录调整
  • • 🟪 新增 Skill — 新的 skill 目录和文件
  • • 🟨 原型产出 — HTML + .md 原型方案
  • • 🟥 代码实现 — 功能代码 + 测试
