# Prototype Designer — 原型与PRD生成

从需求文档出发，先生成原型方案，再输出PRD。

## 使用方式

在对话中直接说 `使用 prototype-designer` 或 `开始原型` 触发。

## 流程

按以下步骤顺序执行，不要跳过。

### 步骤 1：读取需求

- 读取 `docs/requirements.md`，了解项目背景、目标、功能模块
- 如果存在 `docs/architecture.md`，一并读取了解技术约束

### 步骤 2：按模块确认需求

每次聚焦一个模块，向用户确认以下内容：

1. **业务流程**：这个模块涉及哪些角色？核心流程是什么？
2. **页面清单**：需要哪些页面？（如：列表页、详情页、表单页）
3. **核心字段**：表单/列表需要展示哪些关键数据字段？
4. **交互规则**：有什么特殊交互？（如：审批链、状态流转、消息通知）

用户确认后再进入下一个模块。

### 步骤 3：生成原型方案

每个模块输出以下内容到 `docs/prototypes/{模块名}.md`：

```
# {模块名} — 原型方案

## 页面清单
- 页面1（路径、用途）
- 页面2

## 页面一：[页面名]
### 布局结构
（文字描述页面从上到下的布局）

### 核心元素
- [ ] 元素1（类型、说明）
- [ ] 元素2

### 交互说明
- 操作 → 反馈
- 状态流转

### 数据字段
| 字段 | 类型 | 说明 |
|------|------|------|

## 页面二：...
```

完成后请用户确认原型方案。

### 步骤 4：生成 PRD

用户确认原型后，输出 PRD 到 `docs/prd/{模块名}.md`：

```
# {模块名} — PRD

## 1. 概述
- 业务目标
- 涉及角色

## 2. 功能范围
- 功能清单（含优先级 P0/P1/P2）

## 3. 业务流程
- 流程图描述

## 4. 页面规则
- 每个页面的详细规则
- 数据校验
- 异常处理

## 5. 数据模型
- 核心实体及字段

## 6. 非功能需求
- 性能、安全、兼容性

## 7. 变更记录
```

### 步骤 5：汇总

全部模块完成后，在 `docs/prd/SUMMARY.md` 生成汇总索引。
